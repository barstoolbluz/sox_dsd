## Delivered code, behavior and missing qualification

- `src/sdm.c` and `src/sdm.h`: immutable, versioned **exact native-rate**
  profile registry for 2,822,400, 5,644,800 and 11,289,600 Hz. Its 12 entries
  cover `encode.legacy.v1`, `encode.mastering.v1` (`sdm-8`), and the two
  diagnostic controls (`sdm-6`, `clans-8`). An entry's profile ID must match
  the caller's requested exact native Hz; future/unsupported rates and an ID
  for a different rate return null. It cannot select a lower-rate coefficient
  bank by fallback. The original table, all 30 original coefficient payloads,
  and the historical normal and trellis arithmetic remain unchanged.
- New independent `sdm_normal_t` is stack-allocatable and has two old/new
  eight-coordinate banks, previous decision zero at initialization, a scalar
  old-bank-only recurrence, and signbit quantization including negative-zero
  tie behavior. It does not allocate trellis history or silently reset state.
  `sdm_normal_monitor_t` is optional, caller-owned, and maintains continuous
  28-bit rolling windows, excursions, run lengths, overload and nonfinite
  counts, first-failure frame and per-coordinate state extrema across buffers.
  Counters saturate rather than wrap. A nonfinite step does not commit the
  previous decision or active bank. No automatic stabilizer, coefficient
  substitution, or reset was introduced. **No numerical guard bounds or
  qualification certificate were invented:** these require P10 training,
  holdout and long-duration validation.
- The legacy `sdm_init()` **intentionally keeps** its original descending
  `<= rate` selection, 0.5 PCM scaling, normal output and trellis behavior.
  The ordinary CLI/default selection, existing dither behavior, P08 graph
  boundaries and legacy writers are unchanged. No P09 mastering path is
  automatically activated. Normal monitoring is not in the legacy hot path.
- `src/sdm.c` exposes the legacy allocation footprint for measurement only.
  `test/Makefile.am`, `Makefile.am` and `tests/dsd/measure.py` register P09
  executable tests, numeric verification and distribution inputs. Added
  `tests/dsd/test_p09.c`, `test_p09.py`, `bench_p09.py`,
  `sanitize_p09_results.py`, the baseline coefficient-bit manifest and this
  handoff. The external `P09_brief.md` is retained in `docs/dsd/briefs/`.

## Frozen metrology; before any candidate dB comparison

`tests/dsd/reference/analysis-v1/` contains the immutable coefficient bytes,
manifest, synthesizer, analyzer, verifier and candidate runner. The complete
freeze inventory `SHA256SUMS.txt` has SHA-256
`7a5e104099fb18224e589d03b676c0ca3e9c8036eedb87b0fbd1de1d9bee1616`.
The analyzer verifies these hashes before every comparison. The generator
uses `mpmath` at 60 decimal digits; it refuses to replace an existing freeze.
The resulting symmetric binary64 FIR lengths are 9,683 / 19,365 / 38,729
for DSD64 / 128 / 256. Frozen coefficient-byte SHA-256s respectively:

- `1bba6e83a53dbd5a690664dda52bac672eacd18ed8c3f886ffe0a4d2d53cc74b`
- `4be03881c09051bd0c430a1eb1b0386325b83e12661c572ea3a1ebf569f6c167`
- `35b52b0d88fece13662252fbfba076cdd7b80cccf812b4f503520197f3317964`

Each filter passes the *independent executable* FFT response self-test.
Absolute passband error maxima are approximately 1.82e-9 dB; worst observed
stopband responses at/above 24 kHz are -193.23, -194.72 and -198.14 dB,
respectively, exceeding the 180 dB suppression requirement. Exact output
counts and direct time-domain dot-product samples are checked at all three
rates, including zero and non-multiple tail counts. Additional known-answer
tests verify coherent sine phase/amplitude, a -40 dBc second harmonic in
THD+N, seeded noncoherent noise under the specified window/ENBW correction,
and an alternate SciPy FIR/direct polyphase implementation. **Eight analysis
self-tests pass, zero fail.** This certifies the measuring instrument for its
defined scope; it does not qualify any SDM profile.

The frozen analyzer implements a native-rate symmetric FIR, integer delay
compensation, exact 88.2 kHz decimation by FFT overlap-add, two-sided trim of
at least 250 ms, and a retained aligned one-second comparison interval.
997/1000 Hz signals measured over exactly one second use a rectangular
window; otherwise the fixed four-term Blackman-Harris coefficients and ENBW
correction apply. The sine/DC/cosine least-squares fit separates fundamental
power, phase, gain, residual, THD-only diagnostic and SNR. The 20 Hz–20 kHz
THD+N residual removes **only** the DC and fitted fundamental. Power in dBFS
is `10*log10(P/0.5)` with a sine of peak one at 0 dBFS. A separately designed
second filter is a corroboration, not an averaged score.

## Candidate and holdout results: measured, NOT qualified

The P09 analytic scalar-input corpus has a SHA-256 identity for each exact
rate, frequency, source peak and duration. The training case uses a 997 Hz,
-6 dBFS PCM-source tone, and the disjoint holdout case uses 1 kHz, -20 dBFS.
Each test is 1.6 seconds at the **actual native DSD clock**, with at least a
one-second steady comparison after trimming. Input to the scalar kernel uses
the existing 0.5 reference. The corpus bypasses interpolation deliberately,
so it is **not** a PCM mastering integration, stress-soak or release test.
Every profile uses the same analysis-v1 FIR/window/power convention.

All **24 candidate/rate/corpus cases ran without execution failures**. The
ordering by the measured 20 Hz–20 kHz analysis-v1 residual, low to high, was:

- DSD64 training and holdout: **sdm-8**, sdm-6, clans-8, legacy clans-4.
- DSD128 training and holdout: **sdm-8**, clans-8, sdm-6, legacy clans-4.
- DSD256 training and holdout: **sdm-8**, clans-8, sdm-6, legacy clans-4.

For the frozen -6 dBFS 997 Hz training signal, DSD64 residual band levels
were -146.55 dBFS (`sdm-8`) versus -112.24 dBFS (legacy); DSD128:
-197.74 versus -137.35 dBFS; DSD256: -248.66 versus -159.06 dBFS.
The very low DSD256 values approach analytical/numerical precision limits;
do not extrapolate a universal quality or precision ranking from this small
corpus. The original state observations include magnitudes in the millions;
this is recorded, not called runaway. Every tested window had zero 28-bit
excursions and the outputs had no nonfinite monitored states, but this is not
a long-duration stability certificate or interpolation admissibility test.

The selected mastering candidate stays **sdm-8; unqualified**. The required
P10 full composite interpolation, bandwidth prefilter, input-envelope
failure paths, calibrated guard-bound training/holdout, full numeric rate
matrix, 60-second development tests, 30-minute/rate soaks, 1-hour ISA soaks,
production residual/spur targets, and real-world independent source corpus
remain **UNRUN**. No P09 result is a release mastering certificate.

## Performance evidence: INCONCLUSIVE, not a 5% pass

P08 control is the supplied unmodified P08 source built with the same
`--disable-shared --without-libltdl CFLAGS='-O2 -g'` configuration. Control
binary SHA-256 `ed5202962fe9dc6b1f21c971bd0a9c18ccc895218b220fc4e5aefccb54d95082`;
P09 candidate binary SHA-256
`1b40d7dab5f124cb7b4b584fb0a6d9fdff5b518453773c04f5cdc52a173f0fd0`.
Hardware is a virtual AMD EPYC 9V74 80-Core host (available affinity limited
to CPU 0–4), with no host isolation/governor/boost controls. The 9-run
pinned-core preparation probe measured **6.4%** spread, exceeding the 2%
noise admissibility limit (`host-noise.txt`). We did not infer a pass from
any paired median or from the development smoke benchmark.

Using the existing randomized AB/BA paired runner, 15 measured pairs per
workload, two warmup pairs, CPU 0 affinity, `/dev/shm` fixtures/output, and
SHA-256 output comparison:

- Legacy mode: **16/16** repack/null workloads ran, 544 conversions, zero
  execution errors; all performance statuses are `inconclusive-noise`.
  Critical `dff-6ch-repack-small`: median **-3.71%** P09/P08 CPU-time
  change, bootstrap ratio 95% interval **[0.90251, 1.05363]**, 12.15% noise.
- Opt-in `--dsd-mode=auto` native repack: **8/8** workloads, 272 conversions,
  zero execution errors, all eight output SHA-256 comparisons identical and
  every status `inconclusive-noise`. Critical `dff-6ch-repack-small`:
  median **-3.08%**, bootstrap ratio interval **[0.94545, 1.02640]**,
  6.46% noise. The interval does not establish a formal pass because the
  precondition (noise under 2%) fails. Noncomparable auto-mode null work is
  not counted in this set; it is covered separately by legacy-mode runs.
- P09 low-level probe: old legacy allocation **30,336 bytes** vs new
  normal-state **168 bytes** plus optional separate monitor **160 bytes**.
  Scalar one-million-frame monitor overhead is approximately **1.28–1.31x**
  at the three rates; unmonitored performance is not charged this overhead.
  The inherited explicit `sdm -f clans-4` normal and trellis conversions
  remain **byte-identical to P08** in every paired run. The low-level timings
  are diagnostic and do not override the 2% host-noise gate.

The exact comparisons used `bench_read_p02.py --baseline-sox <P08>/src/sox_ng
--sox ./src/sox_ng --working-directory /dev/shm --cpu 0 --pairs 15
--warmups 2`, plus `--operation all --both-arg=--dsd-mode=legacy
--null-extra-arg=--dsd-layout-loss --null-extra-arg=warn` for the first, and
`--operation repack --both-arg=--dsd-mode=auto` for the second. The test used
`--require-comparable-preset p01p02` to prohibit exclusion of previously
comparable outputs. Source command, output identities, CPU timings and
interval/noise decisions are in `paired-legacy/bench-read.json` and
`paired-auto/bench-read.json`. `bench_p09.py` was also run (exit 0) against

brief's +3.20% P05–P08 critical-workload accumulation is not silently
converted into a pass by this inconclusive P09 measurement.

**Formal P09 5% comparative throughput certification remains INCOMPLETE.**
A prepared host with measured under-2% variation and a full bootstrap
interval under the 1.05 ratio threshold is needed. A confidence interval
that straddles 1.05 is inconclusive, even if its median is favorable.

## Scope, evidence and next permitted phase

No independent physical AVX1-only CPU, forced SIMD ISA family matrix or
multihour mastering soak was available. New P09 code uses the scalar normal
kernel without SIMD-tier promotion or a new auto encoder selection. Optional
codec functionality already enabled by `configure` was exercised in generic
checks; no new codec integration was introduced. No cross-ISA byte identity,
hardware compatibility or release-speed claim is made. This P09 delivery is
**complete as the extraction/metrology phase**, subject to a separately
admissible 5% P08-to-P09 throughput gate. It is **not** P10 mastering
qualification or P15 default promotion.

The next permitted implementation phase is **P10**, provided it retains the
exact-rate identities and immutable analysis-v1, completes the full
interpolation/input-envelope and prolonged stability tests, and does not
promote `sdm-8` on the strength of P09 scalar probes. Re-run the formal
throughput gate on an adequately prepared host before claiming acceptance.

The delivery contains the complete original source tree plus all P09 source,
frozen coefficients, self-tests, test fixtures, corpus identities, raw P09
results and this handoff. Previous P00–P08 evidence files are retained byte
for byte, except the required regenerated `P00_SHA256SUMS.txt`. Temporary
workstation paths in P09 JSON command records are normalized by
