## Implementation

- Added additive, versioned `sox_dsd_packed_block_t` and `sox_dsd_read_packed` / `sox_dsd_decoder_process_packed` entry points (`src/sox_dsd.h`, `src/dsd_packed.{h,c}`). The descriptor specifies buffer extent, physical channel/byte strides, LSB/MSB order, first-bit offset, final valid-bit count and valid frame count. Bounds and overflow validation occurs before bit addressing. A returned block **borrows** reader-owned bytes and must be consumed before the next reader block, seek or close.
- DSF returns planar bytes from the *same normalized block cache* already used by expanded reads. Physically MSB-first DSF is reversed once into the cache, then exposed as LSB chronological bits. DFF returns channel-clustered, MSB-first bytes, reuses the current partial cluster, and only allocates a bounded 1,024-cluster batch on demand. Neither path reconstructs 32-bit graph samples. No new independently advancing file cursor is introduced.
- Packed and expanded access modes are mutually exclusive on a handle until a successful seek. Failed mode switching does not advance the reader. The only update of `ft->olength` for packed reads is in the public packed dispatcher. Successful seek resets the access mode and stale error state; EOF and native frame accounting retain their original contracts.
- The packed decoder feeds identical scalar/SSE2/AVX1/AVX2/AVX-512F binary64 FIR state (±1.0) directly from bits, with no table approximations, new SRC, modulator, writer or generic SoX sample-type change. Shared `src/dsd_public.c` downstream SRC and finite-count contracts are reused for expanded and packed inputs. A public test compares complete binary64 output **bit-for-bit** against the expanded reference.
- The CLI adapter opts in with **`SOX_DSD_PACKED_INPUT=1`**; the ordinary expanded path remains the default. When the P14 native-statistics report is enabled, the adapter deliberately falls back to expanded input so that the existing observational report remains authoritative. Use `-V4` to see `P16: native packed input enabled` when the packed adapter is actually selected. The native DSD writer/repack path is unaffected.
- `test/dsd_test_dff_writer` compiles a privately injected copy of `src/dsdiff.c`; its new externally visible reader symbol must be test-renamed alongside the registry symbols. That **test-scoped** link correction has no behavioral effect on the production DFF writer.

## Benchmark and interpretation

Paired development profile: x86-64 GNU/Linux shared/virtualized host, GCC 14.2, `-O2 -g`, static libSoX, 0.5 seconds of DSD256 2-channel source, one mastering-v2 output at 88.2 kHz, 3 repetitions/format. Both paths produce **identical PCM SHA-256** in every trial. Times below are **median process CPU seconds**, not wall-clock guarantees:

- **DSF:** expanded **0.29 s**, packed **0.28 s**; ratio **1.036×**. Median peak RSS 3,324 versus 3,224 KiB.
- **DFF:** expanded **0.29 s**, packed **0.27 s**; ratio **1.074×**. Median peak RSS 3,280 versus 3,288 KiB.
- At the reader-to-DSP boundary the native DSD256 input changes from four-byte expanded samples to one packed bit per sample: measured payload-accounting ratio **32:1** (2 channels × 5,644,800 native frames). **This is not a claim that disk I/O, total RSS or overall pipeline traffic decreased 32×**; native DSF/DFF files were already packed and remain so.
- Simulated descriptor/bit-address checks at **DSD512 (22,579,200 Hz, 5,644,800 frames)** and **DSD1024 (45,158,400 Hz, 11,289,600 frames)** passed both physical layouts at seven-bit initial offset, without invoking a decoder or writer. Observed CPU ~0.26 s and ~0.52 s for those isolated bit-oracle runs. They are **not** high-rate DSP, SRC, sustained throughput, or media interoperability certification.

The paired timings are short and host-specific. They show bounded memory and matched audio, not a universal acceleration or proof of worst-case latency. Before optimizing further, gather longer, noise-controlled workload profiles on physical hosts and verify that the improvement persists. No byte-contribution tables or speculative SIMD packing were introduced.
