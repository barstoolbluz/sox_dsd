## Implementation and source boundaries

- `src/dsd_kernels.h`: private, uninstalled baseline descriptor and block
  interfaces for both FIR and normal SDM; explicit readable FIR spans, scalar
  tails, committed SDM frame prefix and failure status, no new public ABI.
- `src/dsd_dispatch.c`: CPUID leaf checks; SSE2 leaf 1 EDX[26]; AVX leaf 1
  XSAVE/OSXSAVE/AVX and XGETBV(0) XCR0[2:1] gate; conservative fallback when
  the compiler lacks the SSE2 object. Unknown host defaults to SSE2 FIR where
  both CPU and build support it, otherwise scalar. SDM defaults to scalar,
  retaining the certified P10 mastering recurrence pending ISA-specific
  approval. The documented `SOX_DSD_KERNEL_FIR` and `SOX_DSD_KERNEL_SDM` force hooks
  are independent, resolved at context creation, and reject unsupported or
  unknown active-family names without executing an unsupported ISA. The
  earlier P11 `LSX_DSD_*_KERNEL` names remain compatibility aliases with
  lower precedence. See the override-correction addendum below.
- `src/dsd_kernels_scalar.c`: P06 left-to-right binary64 symmetric FIR
  reference and guarded P10 normal SDM reference, compiled without AVX.
- `src/dsd_kernels_sse2.c`: two independent FIR output-time lanes, a
  vectorized direct decoder FIR, and the retained two-lane SDM state-coordinate
  recurrence with scalar time progression and guarded per-frame commit.
- `src/dsd_kernels_avx1.c`: four independent FIR output-time lanes and genuine
  AVX1 state-coordinate math ported from the original `sdm_x86.h` algorithm.
  The isolated TU uses AVX1 rather than an AVX2 alias.
- `src/sdm_normal_commit_i.h`, `src/sdm.c`: factor original P10 guarded
  commit and monitor bookkeeping into a shared inline helper. The scalar
  arithmetic order, bank-swapping rule, quantizer negative-zero decision,
  frame accounting, coordinate bounds, monitor and failure semantics remain
  the same. Legacy `sdm` effect and trellis math in `sdm_x86.h` remain on their
  existing path, to avoid a behavior change outside the P11 normal-SDM scope.
- `src/pcmdsd.c`: context-owned SDM kernel, one block call for a whole
  producer batch, finite/overload/state-bound failures mapped back to
  existing stream errors; scalar candidate is the default.
- `src/dsd_decode.c`: context selection and specialization once per decoder
  process/finish call, not an indirect per-bit callback. Ring alignment,
  independent per-channel state, chronological phase, tails and release
  accounting remain unchanged.
- `configure.ac`, `src/Makefile.am`, `test/Makefile.am`, root `Makefile.am`:
  independent SSE2 (`-msse2 -mno-avx`) and AVX1
  (`-mavx -mno-avx2 -mno-fma`) convenience libraries with
  `-ffp-contract=off -fno-lto`; only P11 TUs gain these flags. Register P11
  executable, phase runner and distributable tests. Do not add whole-program
  `-march=native`, AVX flags, FMA, or AVX2.

## Performance context and limitations

`tests/dsd/results/P11/bench/kernel-timing.json` contains fifteen CPU-time
repetitions for each per-tier *streaming* FIR, block FIR and guarded/monitored
SDM workload, plus warmups. Each ISA is actually executed. The separate
`forced-cli-timing.json` contains two warmups and fifteen randomized
whole-process decode/encode repetitions per tier; it includes CLI startup and
I/O, and compares AVX1 with SSE2. Output hashes must be stable within each
forced tier, but across SDM tiers are never treated as an acceptance oracle.


**Latest correction-verification medians on this host (15 repetitions per ISA tier):**

- fir-single: scalar 74.175, SSE2 34.208, AVX1 20.909 ns/frame.
- fir-block: scalar 73.573, SSE2 49.829, AVX1 62.077 ns/frame.
- sdm: scalar 33.876, SSE2 31.350, AVX1 32.676 ns/frame.
- whole-process decode: scalar 0.173780, SSE2 0.171059, AVX1 0.170524 s/CLI run.
- whole-process encode: scalar 0.043074, SSE2 0.040639, AVX1 0.041800 s/CLI run.

These measurements are host-specific. The streaming FIR on this host favors
AVX1, the separate block FIR favors SSE2, and SDM/whole-graph results vary
with the workload and startup costs. No dispatch preference or guarantee of
performance on older silicon is inferred from these timings. The conservative
FIR SSE2 and SDM scalar defaults remain intact.

`tests/dsd/bench.py --phase P11` is the inherited short-duration development
matrix, not a replacement for repeated P11 kernel or whole-graph comparisons.
No power/thermal stability or dedicated physical microarchitecture
qualification is claimed. No AVX1-without-AVX2 throughput measurement is
available.

## P11 corrective addendum: documented force hooks (2026-10-11)

**Scope:** A follow-up code audit identified that P05 CLI preflight rejected
`sse2` and `avx1` under the documented `SOX_DSD_KERNEL_FIR` and
`SOX_DSD_KERNEL_SDM` environment controls, whereas the P11 dispatcher read
only the undocumented `LSX_DSD_FIR_KERNEL` and `LSX_DSD_SDM_KERNEL` names.
Even `SOX_DSD_KERNEL_FIR=scalar` could pass preflight yet fail to select the
requested kernel. This corrective handoff replaces the original P11 source
archive as the authoritative continuation tree, without modifying the P10
source, numerical coefficients, freeze, certificate, ISA kernels, hot loops,
or conservative auto-selection policy.

**Production corrections** (smallest existing configuration path):

- `src/dsd_dispatch.c`: the documented family-specific names take precedence;
  the earlier `LSX_DSD_*_KERNEL` spellings remain secondary compatibility
  aliases. The existing selector snapshots each context's selected descriptor;
  there is no mutable global state or repeated environment read per sample.
- `src/dsd_plan.c`: remove the P05-era `auto`/`scalar` name whitelist.
  For executable plans, use the existing runtime selector to validate a force
  only if a P11 FIR decoder or composite SDM encoder context will actually
  exist. Unknown and CPU/build-unavailable active forces fail preflight;
  irrelevant forces on inactive families are ignored. Unmodified low-level
  legacy SDM and native-only transcodes remain outside that policy.
- `src/dsd_decode.c/.h`, `src/dsd_public.c`, `src/sox_dsd.h`:
  route a per-decoder explicit option to the existing context-local kernel
  selector. The public `sox_dsd_decode_options_t` appends an optional
  `kernel_fir` field; a non-NULL value has precedence over environment and
  an unsupported value returns `SOX_DSD_UNSUPPORTED` from decoder creation.
  The original version-1 options prefix and `sox_dsd_decode_options_init`
  are ABI-compatible: the original initializer writes only the P07-sized
  record and advertises that size. The **additive**
  `sox_dsd_decode_options_init_extended` initializes the full P11-sized
  record, enabling use of `kernel_fir` without risking an out-of-bounds write
  to allocations made by binaries compiled against the older struct. The
  decoder accepts both known version-1 record sizes, and never reads past the
  caller's advertised prefix.
- `src/pcmdsd.c/.h`: a read-only internal accessor enables assertion of the
  encoder context's selected kernel; no DSP algorithm is modified.
- `src/dsd_kernels.h`: commentary clarifies selector precedence. There are
  no changes to SIMD code, coefficients, numeric thresholds, signal mapping,
  output containers, or performance policy.

**Test corrections:**

- `tests/dsd/test_p11.c` creates actual scalar, SSE2 and AVX1 reconstruction
  and normal-SDM contexts on available hardware and checks requested kernel
  identity, per-context retention, unknown/unavailable tier failures, public
  explicit-option precedence, original-options-prefix ABI canaries, and
  legacy compatibility aliases.
- `tests/dsd/test_p11_integration.py` now forces the documented family
  controls, sets intentionally incompatible legacy aliases to assert proper
  precedence, verifies end-to-end buffer/thread invariance and unsupported
  active-family rejections, and adds a native-only no-context conversion with
  both documented overrides invalid. **29 executable CLI cases** pass.
- `tests/dsd/bench_p11_e2e.py` uses documented controls and conflicts with
  old aliases, preserving the workload, repetitions and conservative policy.
- `tests/dsd/test_plan.py` replaces an inherited P05 assertion that an
  inactive FIR override should fail on a native-only transcode. It now
  expects native-only success and separately exercises active decoder-force
  rejection. **156 planner assertions pass.** This corrects the test's
  P11-incompatible expectation without relaxing any active-family validation.
