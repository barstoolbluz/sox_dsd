## Implemented behavior

- `src/dsd_plan.c` activates the previously planned P07 binary64 DSD decoder
  for explicit/implicit graph reconstruction and private input adapters. Pure
  native/DoP transport remains a native bit path. Processed native DSD output
  and the `pcmdsd` composite modulator stay unavailable until the approved
  subsequent phases. The CLI default remains **legacy**, not `auto`.
- `src/sox_ng.c` transfers the resolved plan into executable graph boundaries.
  It inserts the decoder before automatic and user PCM arithmetic, including
  dither/normalization/rate, and does not insert it twice for an explicit
  leading `dsdpcm` already consumed by input adapters. Native-only transcodes
  do not instantiate any decoder or other DSP effect.
- File-level `-v`, reader-provided replay gain, and parallel `mix`,
  `mix-power`, `multiply`, and `merge` cause reconstruction **before**
  `balance_input`/combining. Each input adapter owns one P07 public binary64
  decoder, a bounded native read queue, a PCM queue, and a finite-file
  lifecycle. File gain operates on binary64 samples before **one** int32
  quantization, so attenuation can protect against overrange clipping.
  `balance_input` does not apply the consumed gain again. Effective PCM rates,
  sample lengths and precision govern combiner bookkeeping without altering
  native file-reader signals. Known native lengths are checked at EOF, and a
  prematurely closed nonseekable stream fails rather than claiming success.
- Parallel DSD at different supported native clock families resolves to the
  common decoder PCM clock; mixed PCM/DSD uses the PCM input clock subject to
  the existing rate-compatibility rules. Finite-file input-adapter
  concatenation completes each decoder independently. Compatible native
  concatenation into one graph decoder remains continuous; `sequence`
  restarts that decoder for each file, even when neighboring native rates
  match. The old native trim seek shortcut is disabled on reconstructed
  chains, preserving sequential filter pre-roll; native-only trim is unchanged.
- `--dsd-mode auto` DSD-to-null now reconstructs PCM without triggering a
  one-bit-output dither/SDM: null has no meaningful output bit precision.
  Output rate/channel/encoding are checked against the resolved plan before
  processing; unsupported modulator/processed DSD requests fail before
  writing the destination header. CLI help and `sox_ng.1` document this
  opt-in behavior and the unsupported state.

## P08 corrective delivery: guard insertion stays in the PCM domain (2026-10-09)

Input: the completed P08 source tree `sox_ng-P08-source-2026-10-09.tar.gz`,
SHA-256 `216e304aa66c321be39adb59c1f6bc40950758e2290d94b7d1548f7555c4b327`.
The identified defect was an unplanned `gain` effect in `--dsd-mode auto -G`
native repacking and terminal DoP, operating on one-bit native samples. The
native bits happened to remain unchanged, but generic sample arithmetic was
prohibited by the P08 contract and added avoidable work.

**Small, isolated implementation:** `src/sox_ng.c` now starts the automatic
headroom guard disabled when the resolved combiner domain is native DSD. The
existing `add_effect()` guard remains unchanged for PCM. An implicit or
explicit graph `dsdpcm` decoder first executes on the native samples, then
reenables ordinary guarded-gain insertion on the resulting PCM signal. A
still-native route skips the otherwise unconditional terminal guard gain.
Private input adapters produce PCM before `add_effects()` and retain ordinary
PCM guard behavior. No change was needed in `src/dsd_plan.c`, `src/gain.c`,
the DFF reader, channel layout handling, or the DSP kernels. Default legacy
mode and PCM-only operation do not enter the new condition.

**New executable regressions:** `tests/dsd/test_p08.py` adds five targeted
cases without introducing an additional runner. Total P08 integration:
**28 pass / 0 fail** (previously 23 / 0). They check four DSF/DFF native
repack combinations against independent bit chronology and unguarded output;
DoP waveform payload and alternating marker bytes against the hand-built
oracle; guard ordering for both implicit and explicit decoders with identical
signed-32 PCM output; nonidentity automatic normalization against explicit
`dsdpcm gain -nh`; and native trim plan versus verbose executed-chain
correspondence. Guarded native and DoP traces contain **no `gain`**; decoded
PCM traces place `dsdpcm` before every `gain`. The two native guard plans
contain no decoder or arithmetic steps; the corresponding PCM plan contains
one decoder. New deterministic plan snapshots are under
`tests/dsd/results/P08/plan-p08/guard_*.json`, and the revised integration
result is `tests/dsd/results/P08/integration/integration.json`.
