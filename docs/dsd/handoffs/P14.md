## Engineering implementation

- `src/dsd_stats.{h,c}` (new): independent chronological native-bit accounting, per-channel exact overlapping 28-bit one-count extrema/excursions and first-frame indices, longest runs, explicit counter-overflow refusal, lossless decimal-string integer serialization, finite-or-null measurement fields, stable JSON v1 writer and stderr summaries. Basic source counters are collected before the adapter/combiner/mastering decoder when reporting is explicitly enabled; normal unreported processing has no numerical changes. Decoder reports snapshot the **selected** FIR kernel, actual profile, certified coefficient-bank identities, consumed/produced frames, gain mapping, filter delay and graph clipping. The isolated, previously existing P10 candidate encoder reports its **actual** SDM kernel, certificate, input scale, committed frames, status/error index and native stability-monitor counters. Candidate tests do not install it in production dispatch.
- Native `dsdstat` in new `src/dsdstat.c` replaces the placeholder in `src/dsd.c`: native-only pass-through samples copied unchanged; ordinary invocation reports exact counters to stderr; `-a` opts into double-precision fifth-order Butterworth SOS level and original-bit 40-100 kHz analysis, plus integrated conventional bands. Digital filters use analog-prototype prewarp/bilinear design, stateful SOS, a 20 ms warm-up exclusion for integrated powers and SACD-style exponential *power* averaging with alpha=2^-19. Distinct dB SACD and dBFS sine-reference labels are not interchangeable; none is called certified physical SACD metrology. There is no reconstructed mastering PCM in the native ultrasonic observer.
- `src/sox_ng.c`, `src/dsdpcm.c`, `src/pcmdsd.{c,h}`, `src/dsd.h`: opt-in `--dsd-report PATH` and truthful status (`complete`, `failed`, `cancelled`). Reports are independent of the audio stream, preflight same-path and existing-file overwrite checks, hardlink/input/output alias refusal and stdout-alias protection (`-`, `/dev/stdout` and other same-stream filesystem paths). Failed conversions can record partial counts and first errors and remove partial audio; successful reports are published only after the output closes. Report write errors fail the command. The established `--dsd-plan` remains non-executing preflight and retains its pre-P14 schema/behavior.
- `src/dsd_plan.c`, `src/Makefile.am`, `test/Makefile.am`, `Makefile.am`: register the native effect, compile only new P14 sources, use P14 as current DSD regression phase, inherit P00-P13 checks and add independently runnable P14 C/Python/numerical gates. An `autoreconf -fi` bootstrap is required before `configure` because automake inputs changed in P13.
- `tests/dsd/{test_p14.c,test_p14.py,test_p14_numeric.py,bench_p14.py}` and `tests/dsd/reference/{p14_report_schema_v1.json,p14_report_golden.json}` (new): native bit-window golden oracle and chunk invariance, >2^53 integers, schema order/evolution validation, representative completed/failing/clipped/DoP/encoder-error/cancellation reports, byte hashes, stdout/report collision policy, real ISA selection and independent SciPy SOS/averaging/band-energy transfer checks. Tests explicitly distinguish P10 interpolation/input-overload errors from SDM state overload events.
- `tests/dsd/{run.py,measure.py,bench.py}`, `sox_ng.1`, `soxeffect_ng.7`: inherited test entry points extended through P14; CLI and manpage guidance accurately distinguishes quiet mode, stderr statistics and report destinations.

No default FIR or modulator ISA/profile was changed: automatic FIR remains SSE2 where available, mastering SDM remains scalar, and neither FMA variant is installed. There are no P13 source changes, no dispatch promotion, no modified audio coefficients, no general PCM cleanup or ABI change.

### P14 development overhead, not dispatch qualification

With a 0.2 s stereo DSD64 native pass-through workload, 1 warm-up plus 3 timed repetitions per arm, unpinned CPU and ordinary process scheduling, the second non-concurrent measurement records these **median wall times** (seconds): native without observer 0.003854; native with basic JSON report 0.008689 (**2.25x**); native with `dsdstat` basic 0.015087 (**3.91x**); native with `dsdstat -a` 0.064292 (**16.68x**). Identical audio hashes in all four arms: **yes**. Larger slowdowns are expected because source-wide 28-bit accounting and full native-rate binary64 SOS analysis are real work, not optimized or disabled guards. These are short virtual-host characterization numbers, **not** a physical-silicon FIR/SDM choice, a general P14 performance guarantee, or justification to promote defaults. They quantify basic counters separately from expensive opt-in analysis.
