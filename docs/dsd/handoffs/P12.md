## Engineering changes

- `src/dsd_kernels_avx2.c` (new): four independent FIR outputs in YMM
  lanes, stride-two window gathering with real full-width AVX2 `vpermpd`,
  scalar exact-span tails, and AVX2-permuted streaming FIR. Normal SDM
  vectorizes eight state coordinates and explicitly handles the lane-3/4
  neighbor boundary. It never evaluates dependent time samples in parallel.
  All guarded state commit, frame counters, monitor accounting and
  overload/nonfinite handling remain owned by the inherited P09/P10 logic.
- `configure.ac`, `src/Makefile.am`, `src/dsd_kernels.h`,
  `src/dsd_dispatch.c`: compile/link AVX2 in an isolated convenience library
  with `-mavx2 -mno-fma -ffp-contract=off -fno-lto`; detect AVX2 only with
  CPUID leaf 7 and OS-enabled AVX state; expose independent FMA capability
  without requiring it for AVX2; fail closed for unsupported forced kernels.
  Scalar, SSE2 and independently compiled no-AVX2/no-FMA AVX1 retain their
  original ISA contracts. Automatic FIR remains conservative SSE2 when
  available, and normal SDM remains scalar.
- `src/dsd_decode.c`: connect AVX2 selection to the existing directly bound
  streaming and flush paths. This is necessary for real production AVX2
  decoding; merely adding the descriptor left an unreachable selected tier.
- `test/Makefile.am`, `tests/dsd/test_p11.c`, `tests/dsd/test_p12_bounds.c`
  (new): extend mocked CPU-feature policy, FIR 1..257 odd-tap cases,
  half-band and dense paths, tails/unaligned/stride accesses, protected
  page-boundary spans, normal SDM 4/6/8 states, guards, monitors and
  cross-buffer invariants.
- `tests/dsd/test_p11_integration.py`, `tests/dsd/test_p12_channels.py`
  (new): 37 forced-tier production CLI scenarios plus 32 executions over
  1/2/5/6 channel layouts, including thread/buffer invariance and negative
  optional-tier selections. Production decoding and the explicitly
  uninstalled P10 candidate encoder are separately identified.
- `tests/dsd/test_p11_numeric.py`, `tests/dsd/bench_p11.py`,
  `tests/dsd/bench_p11_e2e.py`, `tests/dsd/bench_p12_matrix.py` (new):
  preserve P11 defaults while enabling four-tier P12 analysis-v1 and
  fifteen-repeat randomized kernel/end-to-end timing. E2E fixtures cover
  DSD64/128/256 and mono/stereo/6ch controls. CPU time/RSS and output
  reproducibility are recorded for timed CLI runs.
- `tests/dsd/check_p12_isa.py`, `tests/dsd/sanitize_p12_results.py`
  (new), `Makefile.am`: audit object disassembly and isolated build flags;
  add actual P12 test gates to `make check-dsd` and distribution inputs;
  optionally replace machine-specific paths in **P12-only** evidence while
  recording before/after SHA-256 values. No P00-P11 source or recorded
  result is rewritten.

## Performance evidence and dispatch decision

On this *single virtualized AMD host*, the 350,000-frame kernel CPU-time
medians were (scalar, SSE2, AVX1, AVX2 respectively):

- Streaming FIR: **48.80, 26.48, 14.21, 12.63 ns/frame**. AVX2 is 3.86x
  scalar and modestly ahead of AVX1.
- Four-output block FIR: **47.85, 31.14, 25.17, 22.21 ns/frame**. AVX2 is
  2.15x scalar.
- Normal guarded+monitored SDM: **24.74, 21.21, 22.46, 20.78 ns/frame**.
  AVX2 is 1.19x scalar; the state update remains sequential in time.

The 15-repeat short-file DSD64/128/256 end-to-end benchmarks include CLI
startup, reads, writes, profile/graph overhead, the normal SDM guard and
monitor, and per-tier production decoding/candidate encoding. Median decode
wall times on this host were broadly similar or slightly *slower* for AVX2
than scalar, whereas encoding was moderately faster. In DSD256 stereo,
AVX2 decode was 0.0663 seconds against scalar's 0.0638; AVX2 encode was
0.0304 seconds against scalar's 0.0340. DSD256 6ch decode was 0.1963
seconds (AVX2) versus 0.1868 (scalar); 6ch encode was 0.0954 versus
0.1017. These timings are not CPU-class calibration or a basis for changing
existing automatic preference entries.

The longer **0.5 second decode / 0.125 second encode**, one-million-frame
kernel benchmark (`--repetitions 15`) also PASSed in all four cases: kernel,
DSD64 stereo, DSD128 stereo and DSD256 stereo. DSD256 stereo median decode
wall times were **0.388 s scalar**, **0.385 s SSE2**, **0.388 s AVX1** and
**0.390 s AVX2**; its encode medians were **0.099, 0.089, 0.093 and 0.089 s**
in the same order. Thus the full graph does not justify switching the
unknown-host decoder default to AVX2. The measurements remain valid only
for the executing virtualized host, frequency/governor conditions and
specified input sizes.

Run: `python3 tests/dsd/bench_p12_matrix.py --results tests/dsd/results/P12/bench-long --repetitions 15 --kernel-frames 1000000 --decode-seconds 0.5 --encode-seconds 0.125`:
**0** (PASS, 4/4 suites; 15 timed repetitions plus warmups per family/tier).

## Unrun hardware and inherited limits

- This host exposes AVX2 and FMA; the no-FMA AVX2 object is independently
  compiled and audited, but a *physical* AVX2-without-FMA CPU was not tested.
  Mock CPUID/XCR0 cases verify that AVX2 selection does not require FMA and
  that missing OS YMM state prevents AVX2 selection. No `qemu-x86_64` is
  installed here. The earlier P11 Sandy Bridge AVX1-only QEMU qualification
  remains in the preserved P11 handoff and receipts, not newly re-executed.
- Physical Intel and other AMD CPU classes, generic fallback binaries
  built on non-x86 architectures, and optional AVX2-FMA specialization were
  not tested. `avx2-fma` is intentionally unavailable by design, not a
  silently aliased or partially qualified implementation. No vendor-wide
  ISA performance claim is made.
- The separate generic `measure.py` reports inherited P10 full candidate
  interpolation qualification, extensive soaks and an external real-world
  DSD corpus as **unrun**; its scalar/fixture selftest passes are not
  represented as those qualifications. Its short generic `bench.py` reports
  the full optional sampling-rate matrix and physical vendor speed matrix
  as unrun. Neither status is fabricated or promoted to P12-specific proof.
- Build success includes available configured codecs only. No extra
  optional codec or hardware suite is described as passing unless its
  executable produced the corresponding receipt.

## P12 benchmark results-root correction (2026-10-11)

`tests/dsd/bench_p12_matrix.py`: the aggregator resolved each results file
relative to the source root, causing successful external-directory runs to
fail with `ValueError` even though all child benchmarks passed. The first
change replaces `artifact.resolve().relative_to(ROOT)` with
`artifact.relative_to(a.results)`. Results now reference their configured
results root. During the requested negative test, a child rejected invalid
frames before writing an artifact. The aggregator then raised
`KeyError: 'status'` while printing progress, preventing its final FAIL
report from being written. The second one-expression change reads the
optional progress status with `.get('status','FAIL')`, leaving the child's
original exit code and stderr available in the existing result schema.
Subprocess execution, measurements, timing, JSON schema, production
algorithms and kernel selection remain unchanged.
