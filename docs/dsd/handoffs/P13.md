## Engineering changes

- `src/dsd_kernels_avx512.c` (new): independently compiled, non-FMA AVX-512F baseline with eight independent FIR output times; `VPERMPD`/`VPERMT2PD` and an exact-span masked stride-two load; scalar tails for under eight frames; contiguous direct streaming FIR without speculative reads. The guarded normal SDM kernel vectors the *eight state coordinates* across one sample, never independent future samples. It uses a documented pairwise reduction, masked inactive coordinates for orders 4/6, inherited monitor and error/commit semantics, and the established quantizer.
- `configure.ac`, `src/Makefile.am`, `src/dsd_kernels.h`, `src/dsd_dispatch.c`: separate AVX-512 compilation unit, executable feature detection and XCR0 0xE6 check, optional FMA fail-closed semantics, unchanged unknown-host policy. GCC 14's `-mavx512f` **also enables AVX2**. The production AVX-512 descriptor therefore advertises and requires SSE2, AVX1, AVX2 and AVX-512F; mocks verify rejection when AVX2 is missing. The isolated flags suppress AVX-512DQ/BW/VL and FMA, prevent contraction and LTO, and do not affect the baseline executable. No unsupported ISA entitlement is inferred from CPUID AVX-512F alone.
- `src/dsd_decode.c`: bind the new selected FIR tier into both the streaming cascade and its end-of-stream zero-padding and output-count path. This correction is required: the first integration replay showed a selected AVX-512 tier returning decoder stream error 7, rather than producing samples.
- `test/Makefile.am`, `tests/dsd/test_p13.c`: real executable/mock-CPU acceptance (missing CPUID leaf, XSAVE/OSXSAVE, every XCR0 bit, FMA rejection, AVX2 prerequisite), protected-page FIR bounds and independent double/long-double comparisons for all odd 1..257 tap counts across output tails, stride and half-band paths, and normal SDM order/state/monitor/guard tests. The runtime test actually invokes the AVX-512 code on the capable host.
- `tests/dsd/check_p13_isa.py`: object-disassembly evidence that baseline/older tiers contain no ZMM or FMA instructions, AVX-512 has genuine full-width masked/permutation instructions, and the required AVX2 lower-tier compiler dependency is declared. This static audit supplements, rather than replaces, executable tests.
- `tests/dsd/test_plan.py`, `tests/dsd/test_p12_channels.py`, `Makefile.am`: rerun inherited P00–P12 gates; retire the obsolete P05 expectation that `avx512` is unimplemented (test now rejects the still-unavailable `avx512-fma`); extend forced production decode/encode to five ISA tiers and multichannel variants; install actual P13 gates, not only scripts.
- `tests/dsd/bench_p13_matrix.py`, `tests/dsd/bench_p11.py`, `tests/dsd/bench_p11_e2e.py`, `tests/dsd/bench.py`: 15-repeat randomized AVX2/AVX-512 paired kernel and real CLI conversion measurements with per-tier output hashes, warmups, medians, MAD, CPU/RSS where supported, short/long files and single/multithread representative cases. Fix the newly introduced `--threads 2` benchmark case to set `OMP_NUM_THREADS=2`, rather than unintentionally holding every workload at one thread. No dispatch policy is changed by measurements.
- `docs/dsd/handoffs/P13_CHECKPOINT.md` and this handoff: historical source substitution, now-resolved provenance, checkpoints, first-failure reproduction, correction and gates.

The P12 canary's `src/effects.c` alignment fix is inherited unchanged. There are no coefficient, profile, CLI, installed struct layout, native DSD chronology, generic PCM `rate` or default policy changes.

## Kernel/full-graph performance and dispatch

Benchmark matrix: **PASS, 7/7 suites** on this virtualized Intel host, each with 15 repeats and recorded raw observations (`tests/dsd/results/P13/bench/p13-avx512-vs-avx2/benchmark-matrix.json`). The AVX-512/AVX2 median speedup ratios are **3.45x FIR block**, **2.07x single FIR**, and **1.17x normal SDM** in the isolated kernel harness (nanosecond-scale timings; interpret with caution). Whole-conversion speedups do not mirror these figures: across the 12 short/long decode/encode workloads, ratios range **0.944x–1.047x**. On the long six-channel DSD256 case, decode is **0.975x** (AVX2 1.225 s; AVX-512 1.255 s) and encode **1.005x** (AVX2 0.484 s; AVX-512 0.482 s). Some encoder cases regress measurably on this VM; no production speedup claim or automatic policy change is justified.

The child reports retain executed commands, durations, CPU/RSS where supported, output hashes and repeat distributions. These VM figures establish execution and reveal possible full-graph/frequency penalties, but cannot certify a physical CPU class, AVX-512 frequency changes or a new default preference. A preference needs repeatable >=10% kernel benefit **and no material full-graph regression** on representative physical Intel and AMD hardware under controlled affinity, frequency and thermal conditions. Keep the inherited SSE2/scalar automatic defaults.
