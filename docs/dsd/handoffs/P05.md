## Seven corrective areas

1. **Leading explicit reconstruction:** A first `dsdpcm` configures per-input reconstruction *before* input volume, replay-gain scaling and parallel DSD/PCM combination. Its PCM rate, decoder profile, level, and pinned native clock carry into each decoder; the effect is consumed rather than duplicated after the combiner. DSD-only mixes use the highest input mastering rate unless explicitly overridden. Mixed PCM/DSD combinations reject a leading decoder rate incompatible with the existing PCM clock.
2. **Stage-local boundaries:** After explicit `pcmdsd`, generic PCM operations require a subsequent explicit `dsdpcm`; no silent decoder is manufactured. The new decoder resolves against the immediately preceding native clock, including pinned profile IDs after DSD128 remodulation. Duplicate encoders and illegal boundary orders still fail.
3. **Current-clock DoP:** Terminal `dop` derives native Hz from its immediately preceding DSD stage, whether input or explicit modulator; transport Hz is exactly native Hz / 16. Incompatible explicit output clock or precision rejects pre-output.
4. **PCM trim timebase:** A native-input trim that ends in PCM, or in a processed native endpoint, reconstructs before trim. Wholly native trim still uses the native path and retains its seek eligibility. Converted paths do not assert native-seek eligibility.
5. **Implicit native-output channels:** Changed output channel counts schedule ordinary `implicit_pcm_channels` *before* one native encoder, reconstructing DSD first when necessary. Unchanged native channel counts stay on the fast path. Native mode rejects PCM transformations, and P04 layout and identity-loss checks remain authoritative.
6. **Actual one-bit effect semantics:** `dither -p 1` and low-level `sdm` are existing, rate-preserving one-bit modulators; they do not claim interpolation or an approved mastering profile and never receive a duplicate implicit encoder. Ordinary dither remains PCM. Read-only getopts queries supply the precision and selected `sdm -f` filter; mismatched clocks or invalid filters fail before output. Matching-clock low-level dither and SDM were also executed into real DSD files; composite `pcmdsd` remains an unimplemented DSP plan.
7. **Automatic normalization:** `--norm` is an explicit PCM `auto_normalize` plan step at the effective insertion point, before terminal modulation and before compatible trailing native-only no-ops. It triggers reconstruction/remodulation for processed DSD targets. `-G` remains conditional and does not insert an unconditional gain step. Explicit gain and normalization are each represented once. An explicit decode after a modulator keeps normalization on the later PCM side.

## Implemented behavior and changed components

1. **Private domain/type contracts:** `src/dsd.h`, `src/dsd.c` declare
   `DSD_NATIVE`, `PCM_AUDIO`, `DOP_TRANSPORT`, separate native and effective
   input signals, reference-level provenance, versioned profile IDs, exact
   DSD64/128/256 clocks and independent capabilities. DSD512/1024 are present
   but disabled. Pure integer helpers check counts and overflow; decoded
   profile pass/stop/intermediate and effective-bandwidth calculations remain
   in the planning path, not an audio sample loop.
2. **Pure planner:** `src/dsd_plan.c` builds a bounded, inspectable plan from
   parsed input and effect metadata. It classifies native-safe repacking,
   verified no-op/permutation transforms and native trim; generic/unknown
   effects require PCM. Distinct transition steps record implicit/explicit
   reconstruction and modulation; duplicate boundaries, illegal ordering,
   DoP transport misuse and conflicting rates/encodings fail deterministically.
   The output contains policy, selected profile IDs, exact target rates,
   effective bandwidth, reference/inverse-modulator scaling, ordered steps,
   layout provenance, decoder counts and native-trim eligibility.
3. **Early CLI integration:** `src/sox_ng.c` parses the documented explicit
   options, including `--dsd-mode auto|native|legacy`, selection, level,
   clipping, bandwidth and report controls. New `--dsd-plan` is a read-only
   JSON plan exit point for the acceptance harness. `preflight_dsd()` runs
   after user `getopts` and before `open_output_file()` or effect `start`;
   it consults actual destination format handlers and invokes existing P04
   layout checks. A rejected or unavailable path creates no audio output.
   No stateful effect is started speculatively.
4. **Pre-combiner correctness:** Input `-v` and existing replay-gain
   multipliers are represented in the *per-input* plan, before
   `balance_input`; mixed/multiplied/merged DSD streams each receive their own
   PCM reconstruction. Mixed PCM/DSD uses the existing PCM clock; DSD-only
   parallel composition uses the largest intermediate clock. Distinct source
   DSD clocks are supported in planned parallel reconstruction but a native
   destination requires an explicit output rate; concatenation preserves
   original ordered channel identity and requires identical native clocks.
   Differing PCM input rates remain an error. Each sequence segment is
   validated before the first output header and retains its boundary.
5. **Effect and documentation registration:** `src/effects.h`,
   `src/Makefile.am`, `Makefile.am`, `test/Makefile.am`, `sox_ng.1` and
   `soxeffect_ng.7` register/describe `dsdpcm`, `pcmdsd`, `dsdstat`, the
   CLI options and the separate P05 gate. `make check` retains its original
   rule; `make check-dsd` adds the numeric C probe and independent plan CLI
   suite. `tests/dsd/test_plan.c`, `tests/dsd/test_plan.py` and
   `tests/dsd/bench_plan.py` are new executable evidence.

**Execution boundary:** P05 does **not** implement the composite DSD
