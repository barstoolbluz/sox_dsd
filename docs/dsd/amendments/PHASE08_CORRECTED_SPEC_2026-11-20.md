## 1. Purpose, scope and governing authority

This document specifies the Phase 08 route from physical PCM input words through the native binary64 encoder, physical DSD output, and a subsequent native binary64 DSD reconstruction. It identifies the mathematical or observable property required at each boundary, the domain of inputs for which that requirement applies, its applicable tolerance, the authority for that requirement and the argument necessary to establish it for **every** input in that domain.

The last requirement is deliberately stronger than demonstrating that the present executable passed selected tests. A successful finite test or a frozen output hash is not a proof of a universally quantified property over all supported finite streams. Accordingly, each stage below distinguishes **specified**, **established conditionally**, **accepted at a stated engineering assurance tier**, **observed on a finite set**, and **not yet established for the full domain**. A conditional argument names its premises and the evidence needed to discharge them.

### 1.2 Explicit domain of the universal claims

The **qualified-domain claim** concerns a fixed, identified source revision, executable and effective compiler configuration, rather than an unspecified family of future programs. Let a request be defined by its actual input byte stream, parsed format and channel layout, command-line and effects configuration, selected profiles, input and output rates, floating-point environment, selected backend, block partition and source/output descriptor properties.

For successful **PCM-to-DSD64/128** conversion, the domain includes:

- An explicitly eligible `--precision 64` processing graph, with the necessary built-in WAV or FLAC source restrictions and supported effects; exact PCM source rates and profile clocks; checked counts and representable extents. These are not generalized to all legacy handlers or all effects.
- The supported native PCM formats and representations in `ARCHITECTURE.md` §5.1–5.2, with actual endpoint limits: at the coordinator, 1–64 channels; DSF output only in supported roles and its smaller format limit. The source, output and layout requirements must all be satisfied.
- Finite IEEE-754 PCM values, including signed zero, subnormals, distinguishable low mantissa bits and magnitudes above unity. **Finite input representation is not the same as guaranteed safe processing:** transformed intermediate overflow, invalid environments, disallowed channel/rate/layout states, output failures or modulator-envelope violations require a specified failure, not fictitious successful output.
- The selected DSD64/128 certified v3 modulator, with its immutable coefficients, initial state, switching/recovery policy and admissible post-frontend input bound `|x| <= 0.5 + 2^-28`. The default/warn path ordinarily limits admitted native input to `|x| <= 0.5`; strict admission is governed by the separately specified two-source-int32-LSB allowance and the kernel bound.

For successful **DSD64/128-to-FLOAT64** conversion, the domain includes valid supported DSF/DFF/WSD bitstreams (or another expressly eligible native source route), known or handled physical length, representable channel layout, selected mastering decoder (v2 by default, v1 or wideband if explicitly chosen), supported requested PCM clock and `adapt`/`strict` policy. The native PCM64 writer must actually admit the selected output. DFF's byte-completed bit count is not interchangeable with the original pre-padding logical count.

The universal safety requirement also covers **invalid requests and failures**: each must be refused at its prescribed boundary, with non-success status, no false completion report, and no partial failed block presented as successfully committed. Output bytes already delivered to a pipe cannot be rolled back. A general assertion that *every finite input must encode successfully* is **not** part of this specification.

The domain does **not** include arbitrary changed kernels, arbitrary fast-math builds, different uncertified arithmetic environments, absent I/O resources, unqualified rate/profile combinations, low-level experimental `sdm` paths, DSD256+ certification by analogy, hardware/DAC behavior, or automatic native routing before owner approval.

### 1.3 Notation and four kinds of correctness

- `I[f,c]`: the parsed source sample at zero-based frame `f` and channel `c`; `N` source frames, `C` channels, positive integer PCM rate `F_p`. A complete frame holds all `C` samples.
- `F_d`: native bit clock, either 2,822,400 Hz (DSD64) or 5,644,800 Hz (DSD128). `R`: selected encoder working clock, 88,200 or 176,400 Hz respectively for the documented mastering path.
- `z[n,c]`: native-rate, pre-reference and pre-headroom interpolation output; `a[n,c]`: **actual post-warning-clip** binary64 word handed to the modulator, not the earlier SCALED observer value; `q[n,c]` is the one-bit decision represented as `-1` or `+1`; `b[n,c] = (q[n,c]+1)/2` is its binary digit.
- `D`: the correctly parsed chronological physical bits; `Y[m,c]`: final FLOAT64 PCM output at rate `F_o` after reconstruction and the selected level convention.
- `fl(·)`: evaluation under the **specified** binary64 model. The exact mathematical value and a computed binary64 value are different objects. Roundoff allowances must never be introduced into bit-preserving interchange assertions.
- **Exact representation:** identical required data words, decisions, integer counts or serialized physical bits.
- **Exact fixed-model behavior:** identical output given the same actual words, fixed kernel, initial state, operation order and arithmetic model. It does not imply identical answers across all ISA implementations.
- **Bounded numerical correctness:** a production value lies within a justified per-sample or per-frequency bound of the **same specified operator**, with independent coefficients and phase.
- **Audio/product correctness:** named finite measurements or subsequent private/hardware evaluation meet an independently adopted criterion. It cannot be inferred from bitstream or bounded-state correctness alone.

**Logical composition rule.** For a particular admissible request, if every stage maps its actual input to an output satisfying its specified relation, and the stage-to-stage interfaces conserve the actual values, counts, order, state and exceptions, then the entire route satisfies the composition of those relations. This follows by substitution/induction over finite frames and stage transitions. It is valid for **all requests in the claimed domain** only after the stage relations and the interface invariants are established universally for that domain. Testing representative requests does not discharge that antecedent.

### 2.1 Important separation: exact stream identity versus numerical correctness

An accepted physical DSD hash has meaning only for the exact fixture, source identity, chosen backend, arithmetic model, coefficients, parameters and versioned reference. A changed bitstream may be a legitimate changed algorithm or a regression. Conversely, matching an accepted bitstream on 18 or 20 stimuli does not establish the correct gain/interpolation behavior for every possible source. The independent recurrence is entitled to consume the **observed** `a[n,c]` in order to check S7, but doing so says nothing about whether S1–S6 computed the right `a[n,c]`.

Similarly, the candidate-linked `pcm64_encode_probe` and `pcm64_decode_api_oracle` check interface agreement, routing, partition and result consistency. They are **not independent computational authorities** over the candidate's library. A direct high-precision reconstruction model must use independently retained coefficient words, a specified finite-edge operator and an independently justified tolerance, not the candidate API's output as its expected numerical answer.

### 2.2 Existing numerical envelopes and analysis thresholds (scope matters)

**A. Existing FIR envelope, not a new proposal.** `DSD_DESIGN.md` §8.6 (around line 693) specifies a **per-sample FIR difference against its scalar implementation**, in the section's arithmetic and comparison model:

\[
B_{\mathrm{FIR}}=16\,\mathrm{DBL\_EPSILON}\left(\sum_j L_j\right)\left(\prod_j \sum_k |h_j[k]|\right)\max(1,\mathrm{input\_peak}).
\]

Here `L_j` and `h_j` have the stage-length and coefficient meanings of §8.6; `input_peak` is the bound for that comparator's input. The same section allows **at most one int32 LSB** of difference for the **graph samples in its int32-domain comparison**. Section **8.6.1** (around line 728) incorporates the existing expression as its `B_fir` term. These are **already specified tolerances**, not values to be invented by P2 or P3. ## 3. Logical grounding and outstanding universal proof obligations

The following is the actual logical structure needed for an all-input assertion. Each entry distinguishes (i) what existing material establishes, (ii) which universal inference is missing, and (iii) what would establish it without automatically commissioning implementation work. A verified source-to-executable refinement argument may replace exhaustive input enumeration, but a source hash by itself proves **identity**, not **semantic correctness**.

### L0. Route, admissibility, environment and successful/failed execution (S0)

**Existing evidence.** The architecture defines a finite capability matrix, pre-commit descriptor checks, checked frame counts and guarded binary64 environment. Phase 08 includes compiled environment/rounding and close-error controls; 15-mutation ablation still rejects the `fenv_guard_off` and close-error mutants by behavioral contracts. The current manual explicitly keeps native64 opt-in.

**Universal argument required.** Partition all request/configuration/descriptor states into accepted and refused cases. Prove the planner and opened-descriptor checks classify each class correctly; that every DSP entry and drain executes only under the required nearest-even, non-FTZ/DAZ, gradual-underflow model; and that failures cannot masquerade as committed success. A finite set of hostile-state tests cannot cover all possible descriptor races or compiler transformations.

**Assumptions/evidence needed.** A1–A3 and A6 below; a source-level case analysis of route selection and pre-commit acquisition; binary/control-flow correspondence for the actual build; and an invariant over all process/drain/finish/failure transitions, including descriptor close. On unsupported architectures the permitted conclusion is refusal, not qualification.

**Disposition:** route policy **specified**, tested; universal executable conformance **not demonstrated by the return evidence**.

### L1. Finite source representation and channel semantics (S1)

**Existing evidence.** `ARCHITECTURE.md` §5.2 gives exact F64/F32/integer mappings. Phase 08 probes explicitly preserve `2^-40` changes that would disappear through an int32 bridge; there are negative controls for dropped/duplicated tails and swapped channels. The mutation ablation does not replace that exactness requirement.

**Universal argument required.** For each allowed format, prove a representation-preserving byte-to-word decoder with bounded, complete frames and bijective channel mapping. For integer formats, prove the shift/division operates within exact binary64 representability for the admitted widths. Prove by induction that each consumed frame advances one shared frame cursor and preserves the positional channel map, including EOF and short reads. The bit-level proof must include all finite bit patterns, negative zero and subnormals, not merely one fixture class.

**Assumptions/evidence needed.** A1, A2, A4 and A6; audited byte-load/word-transfer and parsed-format code; verified I/O invariants and source-to-binary correspondence. Golden source-word SHA-256 files protect the *selected* stimuli but do not universally prove this representation relation.

**Disposition:** exact mathematical mapping **fully specified**; all-input executable proof **open**.

### L2. Gain and the composite encoder frontend (S2–S4)

**Existing evidence.** The review's independent tone check (`review/anchor-check.md`) computed its own interpolation and checked the public manual's gain and level convention for selected 1-second stereo tones. It rejected the doubly applied file `gain` mutant and independently observed DSD64/128 baseline tones. The current qualification independently checks scalar FIR/source-SRC values at selected positions, and pins FIR coefficients; it does **not** apply one continuous independent source-to-admitted-word computation to every CLI sample. The P15 same-operator and spectral criteria apply within their documented decoder/SRC scope, not automatically as a full encoder-frontend execution theorem. The **existing** FIR-versus-scalar numerical envelope in `DSD_DESIGN.md` §8.6 is already a requirement for its stated comparison; the missing part is the composed source-SRC/interpolation/effect/edge bound, not the FIR envelope itself.

**Universal argument required.** Define a finite linear/source-rate operator including its exact coefficient, phase, boundary and rate-transition selections. Start with `DSD_DESIGN.md` §8.6's existing per-sample FIR envelope and §8.6.1's `B_fir` term, rather than replacing either with a newly invented bound. Prove the input/effect gain is applied once in the required order and the reference/headroom gain once at its later boundary. Prove an implementation-level bound, for **every** admitted finite stream and each output index, between production arithmetic and the same specified operator. In symbols, the desired shape is an independently evaluated interval `L_n <= z_production[n] <= U_n` where the interval width comes from an audited operation count, L1 propagation, coefficient and phase errors, and subnormal allowance. A different smooth interpolator, however accurate for tones, is not itself a same-transfer bound. Nonfinite intermediate and arithmetic-exhaustion cases must have a specified refusal.

**Assumptions/evidence needed.** A1–A4 and A6; independently fixed coefficient/phase realization, finite operator, proof of count/buffer/state invariants, reference convergence and correct rounding model. To turn independently sampled FIR evidence into an all-input claim one needs a structural bound on the **operator and its implementation**, not an arbitrarily denser fixture matrix. If a supported backend uses FMA, contraction and summation differences need explicit bounds, not cross-backend word equality.

**Disposition:** gain placement and retained frontend identity **specified**; v1 design thresholds explicitly recorded and v3 threshold adoption **open under P9**; §8.6 FIR comparator bound **already specified in its narrower domain**; complete native CLI-input-to-admitted-word arithmetic equivalence **open**.

### L3. Headroom, clipping and actual modulator admission (S4–S6)

**Existing evidence.** The 20 November ablation identifies the `clamp_cli`, `clamp_lib` and `dupgain_file` faults as **surviving** after recorded-output comparisons were disabled. The four survivors including half-gain reconstruction are rejected by the one-off independent `anchor-check.md` on their respective selected tones. The clipping/recovery counter checks detect certain other mutants by happenstance, not by proving their computed sample values. The Phase 07 AUTO scan/replay tests bind native pre-gain words, but the SCALED observation precedes warning clipping.

**Universal argument required.** For each rate/mode prove the exact branch partition at the specified thresholds, including equality, adjacent binary64 words, signed zero, all channels, the final interpolation tail and strict-mode allowance. For WARN, the admitted binary64 word equals the **single** specified post-frontend clamp result, with the correct count. For ERROR, no out-of-policy value reaches the kernel and no silent clamp occurs. For AUTO, prove that the peak scan and replay act on identical source-rate PCM and identical pre-gain native-stage sequences, that the reported peak is their actual maximum, and that the nonboosting attenuation formula is applied once. Prove no extra unity clamp occurs at source ingress or any intermediate branch.

**Assumptions/evidence needed.** A1–A4, A6; source-level exhaustive branch reasoning for all finite comparisons; independence of the numeric model from both CLI and candidate-linked probe; explicit arithmetic bounds for the scalar peak/gain calculation, or an owner-selected exact fixed-model interpretation. Kernel-bound checks are a safety condition, **not** proof of correct gain or clamp arithmetic.

**Disposition:** native level policy **authoritatively fixed**; independent selected-tone corroboration **PASS within its limited domain**; all-input admitted-word correctness **open**.

### L4. Certified switched-resonator recurrence, output bits and recovery (S7)

**Existing evidence.** The delivered immutable DSD64/128 certificate/headers and the owner override bind the switched-resonator identities and the `0.5 + 2^-28` certified input envelope. Phase 08 uses independently retained constants and a separate Python recurrence with the **actual** admitted words; isolated recovery-active tests verify decisions and counters for selected sequences. The review's ablation continues to reject the certified-header mutation against frozen constants. The independently frozen constant checks provide meaningful provenance and constant identity even though they are not a universal executable equivalence proof.

**Universal argument required.** First validate the exact certificate's theorem for every admitted sequence in its stated domain, including initial state, switching/recovery policy and all state-coordinate bounds. Then prove the compiled kernel implements the certified **binary64 transition function** at each step. Induction gives: if initial state and coefficients match and each step evaluates the prescribed transition under the protected floating model, all decisions, continuation states and recovery counters match for every finite-length admissible input sequence. Any exception or failed guard follows the specified refusal transition instead. This argument is fundamentally different from checking a finite list of saved bitstrings.

**Assumptions/evidence needed.** A1–A3, A5–A6; immutable source and proof identity; proof checker soundness and certificate-to-compiled-constants correspondence; exact initial-state/branch/rounding semantics, including tie behavior; verified absence of unapproved compiler transformations. The certificate's bounded-state/stability conclusion **does not imply** any universal `q-x` audio spectrum, absence of audible recovery or hardware performance.

**Disposition:** theorem is **claimed within a restricted mathematical/certificate model**, source-bound immutable identity and finite recurrence observations exist; the all-input **compiled executable refinement** remains an additional premise, not discharged by the 15 mutant results alone.

### L5. DSD bit packing, DFF/DSF accounting and physical I/O (S8)

**Existing evidence.** `DSD_DESIGN.md` §4.1 defines DFF chunk spans, audio sizes, the 0x69 completion pattern and the distinction between logical and byte-aligned readable DFF counts. Architecture/validation cover source-derived counts, DSF logical frames, channel mapping, header rewriting and close error. The physical parser and negative controls reject selected channel-swap, dropped/duplicated-tail, DFF-padding and close faults. These are concrete structural observations, not just hash comparisons.

**Universal argument required.** Prove a bit-level mapping from each chronological `q[n,c]` and its index to exactly one serialized container bit and the inverse mapping upon read, with format-specific byte order, channel order/block organization and permitted terminal completion. Prove all header length equations using checked integer arithmetic, including nested chunk sizes, odd-byte external padding, empty streams, truncation and `N` near arithmetic boundaries. Prove every successful close commits the correct header and that a failed close is never reported as success. The required count relation is source-derived; do not calculate the expected count from the writer's own counter.

**Assumptions/evidence needed.** A2, A4, A6–A7; an independently held DSF/DFF format rule set or equivalent normative source, verified parser/serializer inverses and checked-arithmetic invariants. The return supplies no universal independent format proof. A new general parser is **not** a requirement of this specification; an inspection/proof of the existing bounded implementation can satisfy the obligation.

**Disposition:** count/packing rules **specified**, selected positive/negative controls **passed historically**; all-input physical-byte correctness **open**.

### L6. Decoder profile, FIR frequency response and finite-stream operator (S9–S10)

**Existing evidence.** `DSD_DESIGN.md` §§6.1–6.5 specifies the decoder's exact ±1 bit meaning, rate-dependent mastering-v2 bank, finite zero-extension, phase/latency, optional SRC, adapt/strict behavior and frame-count formula. The P15 spectral assurance amendment **accepts** the unchanged source-audited ideal-operator campaign for engineering purposes at its explicitly bounded trusted-base tier: 11,516 historical canonical receipts in 72 SRC-active cells, plus independent exact-arithmetic corroboration on 1,023 distinct intervals. `P15_R6_MATHEMATICAL_PROOF.md` alone established only two complete canonical intervals; it must not be cited as a universal R6 proof of the whole campaign. The amendment expressly leaves arbitrary-input FFT4G execution roundoff, finite-stream behavior and final ELF/source correspondence **not discharged**. The later `P16_AUTHORIZATION_2026-10-20.md` closed the **P15 first-release/default** gate, not its expressly **open** `P15-v1-and-v2-composite-SRC-acceptance` item; this limits what one may infer from a v2 default.

**Universal argument required.** For a chosen profile, prove its source-bound exact coefficient/phase realization; the ideal stationary transfer inequality across the full stated frequency domain at the **accepted assurance tier**, with its assumptions explicit. Separately, prove the finite-stream formula including zero boundaries, centered stages, all priming and final samples, optional SRC finite input, and exact rational half-up output count. Use `DSD_DESIGN.md` §8.6's already specified FIR-versus-scalar envelope and its §8.6.1 `B_fir` component where their comparator assumptions hold; then prove the remaining SRC, finite edges, arithmetic and composition terms against the **same finite operator**, for arbitrary valid bit patterns, output clocks, backends and stream partitions. An alias/flatness frequency certificate for an ideal time-invariant operator does not by itself certify startup, EOF, rounding or actual executable samples.

**Assumptions/evidence needed.** A1–A4, A6 and A8; independently exact tap/source bindings and complete effective finite operator; correct stage-phase and count construction; an operation-level gamma/L1 and subnormal bound or sound interval argument; source-to-ELF correspondence; independent final-SRC coefficient/phase/timebase construction, including FFT execution where applicable. Acceptance of the original interval campaign's `mpmath.iv` trusted-base/provenance risks is a **specified engineering policy**, not a claim of formal transcendental proof.

**Disposition:** ideal-operator spectral acceptance **scoped and conditional on named assumptions**; finite independent numerical cases exist; **universal finite-stream execution accuracy remains open**.

### L7. Decoder level and final FLOAT64 reconstruction (S11)

**Existing evidence.** The Phase 08 **R3 corrective at `595d401`** checks **19 accepted candidate-output** reconstruction fixtures: **18 retained from `894833f`** and **one `gain_effect` case reproduced by the R3 CLI** (`RECONSTRUCTION_REFERENCE.md` lines 1–9, as quoted in `review/corroboration.md`). This is a source-bound regression oracle, **not an independent ideal-operator reference**. Exact SSE2 matching and a `2^-48` alternate-backend absolute bound apply to these fixed cases; same-backend CLI/API parity is checked separately. The ablation shows `decoder_core_halfgain` survives without those accepted words. The independent external `review/anchor-check.md` detects it as a `-6.02060 dB` level error under both preserve and SACD at the tested DSD64 tones; the base's in-band reconstruction differences were at most `5.27e-8` there. That independent check excludes onset/EOF edge regions and does not certify arbitrary decoder input bits or the full filter response.

**Universal argument required.** Compose the finite decoder operator from L6 with the **exact** preserve multiplier 1 or SACD multiplier 2, once and at the documented boundary. Prove the actual FLOAT64 sink carries those finite words in chronological channel order without an int32 conversion, extra fixed gain or missing tail, **subject to the owner-resolved over-unity boundary decision P8**. Independently verify the declared clip predicate, warning, report, error and frame-commit semantics for both `preserve` and `sacd`. To certify numeric correctness for every supported stream, bound each result against an independently evaluated **same-bank, same-phase, same-boundary** decoder calculation; preserve/source scale may be checked exactly as a multiplier, but the FIR/SRC execution has its own derived error. CLI/API equality proves the route agrees with itself, not that it equals the correct operator.

**Assumptions/evidence needed.** A1–A4, A6 and A8; exact profile/level selection and proof of no additional graph gain; correct target FLOAT64 writer; independent matched filter calculation across finite edges. `2^-48` may remain a **fixed regression acceptance** for the retained test matrix but is not automatically an all-input bound or transferable across arbitrary profiles, amplitudes and implementations.

**Disposition:** level factor and finite operator **specified**; 19 source-bound candidate outputs provide regression protection and the tone check gives limited independent corroboration; **FLOAT64 WARN/ERROR over-unity behavior remains an owner decision (P8)**; universal numeric reconstructed-payload correctness **open**.
