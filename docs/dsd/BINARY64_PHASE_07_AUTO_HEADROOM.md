# Binary64 Phase 07: AUTO headroom scan and replay

**Status:** Implemented for explicit `--precision 64` on the certified native DSD64/128 PCM-to-DSD and DSD-to-DSD conversion shapes. No change to default precision-auto routing.

A finite, interleaved binary64 PCM stream at the encoder's source sample clock is captured once in an owned temporary file, after all permitted gains, channel role mapping and any DSD reconstruction. No 32-bit PCM intermediate or native-rate temporary storage is used. The existing encoder frontend runs in peak-only mode over the captured stream's input and complete EOF drain; all channel peaks contribute to one attenuation decision. Before replay, the encoder is destroyed, the temporary file flushed and rewound, and a new certified encoder selected with the same model/backend profile. Only replay-generated DSD bits reach the output writer.

The owner-approved DSD64/128 certified encoder policy applies: warning ceiling `0.5` modulator units, **not** the earlier unconditional `0.45` stability margin. If `P` is the reference-scaled peak of all scanned channels and the complete tail, common gain is `1` when `P <= 0.5` and `0.5 * (1 - 1e-12) / P` otherwise. This gain neither boosts low-level source content nor adds a second default 0.9 cut. Existing frontend reference scaling is independent of this attenuation.

The bounded disk spool scales with `captured_source_frames * channels * sizeof(double)` and not the DSD bit clock. Its write/read/rewind/close errors latch and reject conversion. Output opens only after scan success and model verification. This does not provide whole-file atomic output for late replay/write failures. The original source is never reread after scan, including pipe sources. Cancellation checks run in capture and replay loops. Report JSON adds `processing.headroom_scan` with the measured peak, common gain, capture and scan counts, tempfile byte count, source clock, profile/backend identity and individual timings; replay encoder measurements remain authoritative.

This path does not enable a new DSD rate, modulator, clock, floating-point mode, source reader, special output or non-permutation remix. `--precision auto` continues to select the original legacy effects graph until the owner explicitly approves native auto routing.

Acceptance: `make check-pcm64 PCM64_SUITE=headroom`. The private `pcm64_headroom_probe` independently compares pre-gain `LSX_PCMDSD_STAGE_NATIVE` words bit-for-bit from the production frontend across passes, including all channels and EOF; checks scaled peak against the encoder's report; and rejects deliberately quantized-spool and omitted-tail mutants. It also checks checked temporary storage fault handling. The Python suite exercises the physical CLI, reports, genuine DSD carriers, nonseekable DFF sources, compatible legacy routing and destination safety. Neither test changes frozen DSP coefficients or modulator recurrence.
