# P21 high-rate code audit and corrected handoff

**Audit date:** 2026-10-23. **Original snapshot:** `9535f565e`, from `sox_dsd-9535f565e-working-set.tar.zst` (SHA-256 `d35f923164aeed938db44b96f8b24cf1b547ae282169a27ad5695718d9726d73`). **Scope:** source correctness after the P21 operator's authorization of DSD512 and DSD1024. This review does not question that authorization or propose additional qualification studies.

**Verdict:** **FAIL for the supplied, unmodified source. PASS for the corrected source against all host-side tests executed here.** The supplied code has two newly exposed authorization/preflight gaps, an unsupported endpoint combination, and an existing destructive failure path. A historical P10 unit test also contradicts P21. All are corrected in the accompanying 14-file patch. The finding is a host-code verdict, not a claim about playback devices or native operating-system qualification.

## Actionable defects and corrections

1. **HIGH — Arbitrary high native rates accepted as supported reader clocks.** `src/dsd.c:42-64`, `lsx_dsd_capability_check()`. After P21 raised the upper bound to DSD1024, the inherited unconditional read-allow branch also permitted noncanonical high labels with no authorized rate row, such as 11,289,601, 22,579,201 and 30,000,000 Hz. Syntactically valid DSF, DSDIFF and WSD files carrying those labels were accepted. **Correction:** Only retain the old noncanonical-reader compatibility allowance at or below DSD256; above it require an exact table row with `LSX_DSD_READ_NATIVE`. Refuse invalid enum members. Regression tests exercise all three readers and the registry; low-rate compatibility is explicitly retained.

2. **HIGH — Native DSF/DSDIFF write requests could be silently substituted, and an existing destination overwritten.** `src/formats.c:1288-1313`. The original pre-open gate checked only the two exact new rates; both were now authorized. A default/legacy request such as `-r 22579201` passed that gate, then the generic negotiator selected DSD1024 instead. A request above DSD1024 was also rounded down. This was reproduced with the original binary: the command succeeded and emitted a DSF file at 45,158,400 Hz instead of the requested 22,579,201 Hz. **Correction:** Reject noncanonical high native write rates before `fopen("w+b")` and before format negotiation, without changing low-rate behavior. Public API tests and 16 CLI cases require both failure and byte-for-byte preservation of a preexisting destination.

3. **MEDIUM — WSD write was reported as authorized despite having no writer.** `src/dsd.c:42-54`. The capability checker previously selected `LSX_DSD_WRITE_NATIVE` for every non-DoP endpoint, including WSD. The available WSD endpoint is read-only; P21 authorizes WSD *reads* at both high rates, not writes. **Correction:** Explicitly reject the WSD-write operation for every rate. Direct tests confirm high and low clocks.

4. **MEDIUM — Invalid output channel counts could destroy an existing file before the writer rejected them.** `src/formats.c:1293-1303`, `src/dsd.h:167-169`, `src/dsf.c:150`, `src/dsdiff.c:468`. Direct API callers could request seven-channel DSF or 1,001-channel DSDIFF, have the file opened/truncated, and then fail at format writer startup. This predates P21 but is now independently verified on P21 high clocks. **Correction:** Reject impossible channel counts before output opening, with shared constants matching the actual writer limits. The test checks that a preexisting destination remains unchanged.

5. **MEDIUM — The live P10 unit suite was left in the pre-P21 regime.** `tests/dsd/test_p10.c:51-111`. Independently running `./test/dsd_test_p10 --unit` on the uncorrected P21 code failed immediately because it expected `lsx_pcmdsd_create(...,22579200,...)` to return `SOX_DSD_UNSUPPORTED`. It also expected the default profiles to remain v1 and v2 to be unqualified. **Correction:** Invert the obsolete assertions and verify both high clocks now default to qualified v2 while exact-ID private candidate creation continues to select the still-unqualified v1. The corrected P10 suite passes **105,499 assertions**. The v1 coefficient/state replay path was not changed.

6. **LOW — Live help and source-facing documentation described the closed regime.** `src/sox_ng.c:3344,3919`, `README.md:22-31`, `docs/dsd/README.md:15-23`, `sox.1:1491-1498`, plus stale test comments. The CLI's encoder-help line mentioned only `v1`; the top-level README and manual said the high rates were disabled/not yet shipped. **Correction:** Advertise v1/v2 versioned IDs and the P21 endpoint capabilities. Historical briefs, sealed P18 ledger, manifests and receipts remain historical and unchanged. The CLI integration suite now checks the live help.
