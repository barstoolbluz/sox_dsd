## Numerical equivalence and P15 status

The retained optimization is **classification 1: bit-exact relative to the frozen implementation under the stated build and execution conditions**. The sole production change is `src/rate_poly_fir0.h`, final SHA-256 `c1626c26f7ba8d64f2b69752906948b527923745313d13c41f78c47046552591`. It changes integer phase scheduling and evaluates two independent rational FIR outputs together. Coefficients, interpolation policy, FFT4G, halfband filters, native DSD reconstruction and ISA dispatch remain unchanged. The full argument is in `docs/dsd/SRC_RUNTIME_OPTIMIZATION_PROOF_2026-10-17.md`; exact original header bytes remain in `tests/dsd/reference/src_optimization/`.

### Why the introduced numerical error is zero

Write the original integer clock as `A=qL+r` and its increment as `M=uL+v`, with `L,M>0` and `0≤r,v<L`. The candidate uses `c=(r≥L−v)`, then updates `q+=u+c` and `r+=v−cL`. This is exactly the quotient and remainder of `A+M`. The subtraction form avoids constructing a potentially overflowing `r+v`. Induction therefore gives the same input start, coefficient phase, output count, consumed input and retained phase as the original division-based loop. The proof covers valid stage states where the original integer operations are defined.

Each output still begins at positive zero and accumulates coefficient-first products in ascending tap order. Pairing interleaves two complete dot products; it does not split or reassociate either output's reduction. The second output's input window is checked before its pointers are formed, and an odd tail uses the original scalar arithmetic. Corresponding rounded operations therefore receive identical operands. Under the contract below, the error introduced by this transformation is exactly zero. This says nothing new about the original filter's absolute error against an ideal real-arithmetic response.

The option requires `LSX_RATE_ORDERED_OPT=1`, no `__FAST_MATH__`, and `FLT_EVAL_METHOD==0`. Compared builds also use `-ffp-contract=off` and prohibit reassociation. Contraction cannot be detected portably by the preprocessor, so the build flag is part of the qualification contract. Execution assumes finite supported audio values, valid nonoverlapping stage storage and the same floating-point environment. Unknown or excess evaluation precision selects the original implementation; ordinary builds remain on that default path. Calls whose reserved output bound is at most two also use the original body. Compiler correctness is an assumption, supported by generated-code inspection and differential tests rather than a formal compiler proof.

### What was checked, and its limits

The independent test includes actual `rate.c` and instantiates archived original headers alongside production functions. Each successful configuration performs 768,060 checks and compares 5,409,850 binary64 sample words exactly. Coverage includes variable and fixed rational FIRs, unchanged halfband controls, phase boundaries, short and odd calls, exact FIFO spans, signed zeros, cancellation, subnormals, four rounding modes, 288 streamed cases and 50 complete private binary64-adapter cases. Final O2 and O3 builds pass; the x87 build passes with `FLT_EVAL_METHOD=2` and the fallback selected. Raw commands, hashes and results are in `tests/dsd/results/SRC_RUNTIME_OPTIMIZATION_2026-10-17/agent_dsd/correctness-final/results.json`.

Whole-CLI equality is asserted only between baseline and candidate using the same input, parameters and buffer size. The separate 10-second stereo 48→44.1 kHz diagnostic exposes inherited limits: both builds truncate output with 32- and 64-byte buffers. Both produce the expected 441,000 frames with 128- and 256-byte buffers, but the output hashes differ between those buffer sizes in both builds. Baseline and candidate hashes match at each individual buffer size. Thus correct length and same-configuration equality do not establish whole-CLI invariance across buffer sizes. The raw diagnostic is `work-evidence/small-buffer-diagnosis/diagnosis.json`. Truncated conversions are unsuitable for accepted throughput claims; their behavior was retained as a finding rather than credited as faster processing.

The same-executable FIFO benchmark compares original, recurrence-only and paired functions with production structures. This reduces unrelated whole-executable layout confounds, but function layout, register allocation and compiler transformations can still differ between arms. It supports interpretation of the implementation choices without fully isolating the causal contribution of pairing. Its complete raw output is `tests/dsd/results/SRC_RUNTIME_OPTIMIZATION_2026-10-17/agent_dsd/real-fifo-final/timing.jsonl`; exact sample validation comes from the differential suite, separately from timing checksums.

### Operator identity is separate from certification

The reviewed exporter comparison covers all 24 nonidentity P15 rate pairs: 43 initialized stages, 59,854 coefficient words and 123,904 FFT-bin words agree exactly, together with graph and scheduling metadata. Twelve graphs contain the modified rational FIR family: each of 88.2, 176.4 and 352.8 kHz to each of 48, 96, 192 and 384 kHz. The other twelve provide unchanged-family controls. Exporting initializes and describes stages; it does not execute their FIR functions. Actual execution is established separately by the kernel, adapter and CLI evidence. Raw snapshots and comparison metadata are at `work-evidence/operator-identity-final-reviewed/`.

All 24 captures nevertheless carry a shared source identity that includes the changed header. Existing source-bound receipts therefore cannot be presented as candidate receipts, even for an unchanged execution route or a default-off build. The original receipts, source pins and campaign outcomes remain archival records for their original identities. A reviewed equivalence bridge could reuse mathematical bounds for the identical operator and coefficient words; the current raw-hash checks do not implement that bridge automatically. The new captures and equivalence argument make the change reviewable without rewriting historical evidence.

Zero introduced error does not close the outstanding arbitrary-input FFT4G arithmetic bound or full composite spectral obligations. The original 0.0001 dB passband-ripple and −160 dB coherent-alias requirements remain unchanged. Empirical sample equality, coefficient identity and faster execution are insufficient to certify those absolute bounds. **P15 release/default promotion remains false.** The detailed obligation mapping is in `docs/dsd/SRC_RUNTIME_OPTIMIZATION_P15_ASSESSMENT_2026-10-17.md`.

The eight historical physical P/S-matched DSD256 comparisons retain their historical `PASS-SCOPED` status. Their native mastering routes reconstruct to 176.4 kHz; final 176.4 kHz uses identity SRC and 352.8 kHz uses a DFT stage. Those native paths do not execute the modified header. A rebuilt legacy comparator can execute the optimized rational SRC, however, so historical speedup ratios do not automatically transfer to that changed comparator. Current virtual-host observations provide no new physical-host qualification.

Evidence completion is also kept explicit. `work-evidence/final-paired/measurements.json` remains the original `RUNNING` receipt with 1,761 rows. Final analysis uses its 48 complete cases and a separately rerun last case; `work-evidence/primary-last-case/completion.json` records that rerun as `PASS` with 36 rows. This recovery preserves the incomplete original and does not relabel it as a completed run.
